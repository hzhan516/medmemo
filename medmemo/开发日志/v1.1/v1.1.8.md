# v1.1.8 — 版本显示与更新通道统一

`完成时间：2026-06-26`

## 版本概述

v1.1.8 是一次 **版本元数据与显示层 hotfix**，聚焦解决 Issue #138 中暴露的版本号不一致、更新弹窗字段缺失、默认更新通道来源不统一以及 CI 自动发布版本格式错误的问题。

- **版本号同源**：`wails.json` 作为版本唯一来源，同步升级 `web/package.json` 与 `web/package-lock.json` 到 `1.1.8`。
- **后端版本接口标准化**：新增 `GetVersionInfo` Wails 绑定，统一返回 `version / display_version / build_number / channel / prerelease_label / prerelease`，供 About 页与底部状态栏使用。
- **更新弹窗字段补齐**：扩展 `UpdateInfoResponse` 与 `update:available` 事件 payload，前端 `UpdateBanner` / `UpdateModal` 可直接使用 `display_version`、`prerelease`、`prerelease_label`、`build_number`。
- **默认更新通道统一**：
  - stable 正式版构建默认通道为 `stable`
  - prerelease / dev 构建默认通道为 `beta`
  - 通过 Wire 注入 `ProvideDefaultUpdateChannel()`，Config Loader 与 Updater Service 使用同一默认值
  - 用户显式配置与 `MEDMEMO_UPDATE_CHANNEL` 环境变量仍优先
- **CI 发布版本格式修复**：`build-and-release.yml` 在 branch push（main / release/**）时统一生成 `v1.1.8-Pre-release-build.N` 并标记 prerelease，禁止 main 自动生成 `1.1.8.N` 这种稳定版本。

**关键原则**：版本信息单一来源、更新通道语义一致、构建产物自描述、不对业务逻辑产生副作用。

## Stage 2: 版本信息接口标准化

### 变更

- `pkg/models/version.go`（新增）
  - 定义 `AppVersion` 结构体：`Version / DisplayVersion / Channel / Prerelease / PrereleaseLabel / BuildNumber`
  - 实现 `ParseAppVersion(v string) AppVersion`
  - 支持 `v1.1.8`、`1.1.8`、`v1.1.8-Pre-release-build.123`、`v1.1.8-build.123`、`1.1.8.123`、`dev` 等格式
  - 统一输出带 `v` 前缀的 `Version`，`DisplayVersion` 去掉 build 号但保留预发布标签
  - 无预发布标签且 build 号为空时 `Channel = stable`，否则 `Channel = beta`

- `wails_app_feedback.go`
  - 保留 `GetVersion()`（前端 `useVersionNotes.ts` 仍依赖它判断 `version === "dev"`）
  - 新增 `VersionInfoResponse` 结构体
  - 新增 `GetVersionInfo() (*VersionInfoResponse, error)`，调用 `models.ParseAppVersion(version)` 并映射字段

### 收益

- About 页与状态栏拿到一致的 `display_version`，不再直接显示带 build 号的内部版本。
- 后续只需要升级 `wails.json` 并重新构建，所有版本显示入口自动刷新。

## Stage 4: 默认更新通道统一

### 变更

- `wire.go`
  - 新增 `ProvideDefaultUpdateChannel() models.UpdateChannel`，基于 `models.ParseAppVersion(version).Channel`
  - 在 `InitializeApp` 的 `wire.Build` 中注入

- `main.go`
  - `NewAppConfig(defaultChannel models.UpdateChannel)` 调用 `config.NewLoader("", defaultChannel).Load()`

- `internal/infrastructure/config/loader.go`
  - `NewLoader(configPath string, defaultChannel models.UpdateChannel)`
  - `loadDefaults` 与 `toDomain` 的 Channel 回退均改为使用 `defaultChannel`
  - 保留 `MEDMEMO_UPDATE_CHANNEL` 环境变量覆盖能力

- `internal/application/updater/service.go`
  - `NewService(u port.Updater, i port.Installer, defaultChannel models.UpdateChannel)`
  - 用 `defaultChannel` 覆盖 `DefaultUpdateSettings()` 中的 Channel

### 行为

| 构建版本 | 默认更新通道 |
|---|---|
| `v1.1.8` / `1.1.8` | `stable` |
| `v1.1.8-Pre-release-build.123` | `beta` |
| `dev` | `beta` |

`ProvideDefaultUpdateChannel()` 对 `version == "dev"` 显式返回 `ChannelBeta`，避免开发构建默认进入 stable 通道。

### 收益

- stable 用户不收到 prerelease 版本。
- beta 用户可收到 stable + prerelease 版本。
- 配置默认值与 Updater Service 初始值一致，避免 `Startup` 覆盖时产生通道跳变。

## Stage 5: CI 发布版本格式修复

### 变更

- `.github/workflows/build-and-release.yml`
  - 移除 `BRANCH` 判断与 main 分支生成 `BASE_VERSION.RUN_NUMBER` 的逻辑
  - branch push（main / release/**）统一生成 `v${BASE_VERSION}-Pre-release-build.${RUN_NUMBER}`
  - `PRERELEASE` 输出统一为 `"true"`

- `.github/workflows/release.yml`
  - 无需修改。tag push 时直接使用 `github.ref_name`（如 `v1.1.8`）作为版本

- `scripts/build/wails-build.sh`
  - 无需修改。脚本原样接收 `<os> <version>` 并透传给 `-X main.version=${VERSION}`

- `Makefile`
  - `LDFLAGS` 中 `main.version` 从 `$(VERSION)` 改为 `v$(VERSION)`，与 tag release 行为一致
  - `release-local` 目标传参从 `$(VERSION)` 改为 `v$(VERSION)`

### 验证

```bash
rg -n "BASE_VERSION\.\$\{RUN_NUMBER\}|BASE_VERSION\.\$RUN_NUMBER|\"\$\{BASE_VERSION\}\.\$\{RUN_NUMBER\}\"|\"\$BASE_VERSION\.\$RUN_NUMBER\"" .github/workflows/
# 预期：无匹配
```
