# v1.1 Prompt Engineering Guide — Memory Injection

> 🌐 [中文版本](../i18n/zh-Hans-CN/design/v1.1-prompt-engineering.md)

> This document describes the prompt design, formatting templates, and token budget strategies used in MedMemo v1.1 memory injection. It is intended for backend engineers, AI integrators, and technical reviewers who need to understand or modify how historical memories are fed into LLM context windows.

---

## 1. Design Principles

Memory injection prompts follow three core principles:

| Principle | Rationale |
|:---|:---|
| **Non-intrusive** | Injected memories must not disrupt the natural conversation flow. The LLM should treat them as soft background context, not rigid instructions. |
| **Attribution-aware** | Every injected fact must carry its source signal (confidence score, timestamp) so the LLM can calibrate its reliance. Low-confidence facts are phrased tentatively. |
| **Compliance-first** | Sensitive facts (`IsSensitive = true`) are excluded by default. No PII, medication names, or diagnostic conclusions enter the prompt without explicit user approval. |

---

## 2. Injection Trigger Conditions

Memories are not injected on every turn. The `MemoryRetriever` evaluates two trigger signals:

### 2.1 Entity Mention Detection

```go
func detectEntityMentions(currentMsg string, facts []*ExtractedFact) []*ExtractedFact
```

- Splits `currentMsg` into tokens (simple whitespace + punctuation segmentation).
- For each approved fact, checks if `fact.Subject` appears as a substring in any token.
- Returns matching facts sorted by recency.

**Why simple substring matching instead of semantic NER?**

- Latency budget: trigger detection must complete in <5ms.
- The downstream semantic search (sqlite-vec) already provides high-quality recall; entity mention detection is a fast pre-filter to skip the vector search when no overlap exists.
- Future improvement: replace with ONNX NER if benchmark shows >10% false-negative rate.

### 2.2 Session Gap Detection

```go
const SessionGapThreshold = 10 * time.Minute
```

- If the last message in the current session is older than 10 minutes, the retriever assumes the user may have lost context.
- It automatically recalls the top-N most relevant facts from the session history (not all facts, to avoid token bloat).

## 3. Memory Formatting Template

### 3.1 Core Template

```go
func FormatMemoriesForInjection(facts []*ExtractedFact, maxTokens int) string
```

**Output format** (Chinese, aligned with MedMemo's UI language):

```
[相关背景信息]
1. {subject} {predicate} {object}（置信度: {confidence}）
2. {subject} {predicate} {object}（置信度: {confidence}）
...
```

**Example**:

```
[相关背景信息]
1. 用户 提到 最近一周睡眠质量较差（置信度: 0.85）
2. 用户 有 高血压家族史（置信度: 0.72）
3. 用户 正在 服用维生素D补充剂（置信度: 0.68）
```

### 3.2 Confidence-Level Wording Rules

| Confidence Range | Wording Style |
|:---|:---|
| ≥ 0.80 | Stated as fact: `用户 提到 ...` |
| 0.60 – 0.79 | Prefaced with hedge: `用户 曾提及 ...` |
| < 0.60 | Excluded from injection (filtered by `ConfidenceThreshold = 0.6`) |

**Why confidence-based hedging?**

- Facts extracted by LLM may contain hallucinations. Lower-confidence facts are phrased as "user once mentioned" rather than absolute statements, reducing the risk of the LLM treating uncertain information as ground truth.
- This aligns with MedMemo's compliance stance: the tool provides reference information, not diagnoses.

### 3.3 Sensitivity Exclusion Rule

```go
if fact.IsSensitive {
    continue   // Skip — never inject sensitive facts
}
```

Facts flagged as sensitive (e.g., containing phone numbers, IDs, or names detected by `desensitizer.RuleEngine`) are completely omitted from the formatted output. This is a hard rule with no override in the current version.

## 4. Token Budget Management

### 4.1 Budget Allocation

```go
const (
    MaxInjectionTokensRatio = 0.20   // 20% of system prompt budget
    DefaultMaxInjectionTokens = 500
)
```

The injection text is capped at 20% of the total system prompt token budget (default 500 tokens). This prevents historical memories from overwhelming the current conversation context.

### 4.2 Eviction Strategy

When formatted memories exceed the token budget:

1. **Sort** by composite score: `score = confidence * time_decay_factor` (higher = more relevant).
2. **Truncate** from the bottom — remove lowest-scored facts first.
3. **Re-format** the remaining facts and re-count tokens.
4. If a single fact exceeds the entire budget, skip injection entirely for this turn.

**Why LRU is not used here?**

- Memory injection prioritizes **relevance** over **recency**. A highly relevant fact from three weeks ago (e.g., chronic condition) is more valuable than a generic fact from yesterday.
- The composite score already incorporates time decay, so the eviction order naturally balances both dimensions.

### 4.3 Token Counting Method

```go
func estimateTokens(text string) int {
    return utf8.RuneCountInString(text) / 3   // Approximate: 1 token ≈ 3 runes for Chinese
}
```

- Uses a lightweight heuristic rather than importing a full tokenizer.
- For Chinese-dominant prompts, the 3-runes-per-token approximation is empirically within 10% of actual token counts for the target models (GPT-4, Kimi, Qwen).
- Future improvement: integrate a local BPE tokenizer for exact counting.

## 5. System Prompt Integration

### 5.1 Full System Prompt Structure

```
{BaseSystemPrompt}

{ComplianceDisclaimer}

{InjectedMemories}   // ← v1.1 dynamic section

{CurrentTurnContext}
```

**BaseSystemPrompt** (static):

```
你是一款健康咨询信息工具，不诊断、不治疗、不开具处方。
你的职责是提供结构化健康信息参考，帮助用户理解症状、就医流程和科室选择。
紧急情况请建议用户拨打120。
```

**ComplianceDisclaimer** (static, per-session):

```
本工具仅提供健康信息参考，不诊断、不治疗，紧急情况请拨打120。
```

**InjectedMemories** (dynamic, per-turn):

```
[相关背景信息]
1. ...
2. ...
```

### 5.2 Injection Position Rationale

Memories are placed **after** the base system prompt and compliance disclaimer, but **before** the current turn context. This ordering ensures:

1. The LLM first understands its role and boundaries (base prompt).
2. Then receives historical context (memories) as supplementary background.
3. Finally focuses on the immediate user message (current turn).

Placing memories too early risks the LLM treating them as rigid instructions. Placing them too late reduces their influence on the response.

## 6. Switchable Injection

### 6.1 Global Switch

```go
func (r *MemoryRetriever) SetEnabled(enabled bool)
func (r *MemoryRetriever) IsEnabled() bool
```

- Persists to a boolean field in the retriever struct.
- When disabled, `RetrieveForContext` returns an empty slice immediately.

### 6.2 Per-Session Switch

```go
func (r *MemoryRetriever) SetSessionEnabled(sessionID string, enabled bool)
func (r *MemoryRetriever) IsSessionEnabled(sessionID string) bool
```

- Stored in an in-memory map (`map[string]bool`), session-scoped.
- Allows users to say "let's change the topic" — the frontend can call `SetSessionEnabled(sessionID, false)` to pause injection without affecting other sessions.

### 6.3 Prompt Impact

When injection is disabled, the system prompt simply omits the `[相关背景信息]` section. No placeholder text is inserted, keeping the prompt clean and saving tokens.

## 7. Compliance Guardrails in Prompts

### 7.1 Forbidden Content Filtering

Before injection, each fact undergoes a compliance pre-check:

| Content Type | Action |
|:---|:---|
| Diagnostic conclusion (e.g., "你患有XX病") | Reject fact at extraction time; never reaches injection |
| Medication dosage recommendation | Reject fact; flagged by compliance interceptor |
| Specific treatment plan | Reject fact; flagged by compliance interceptor |
| Sensitive PII (`IsSensitive = true`) | Exclude from injection |

### 7.2 Emergency Symptom Handling

If the current user message triggers an **A级-立即就医** emergency keyword (e.g., chest pain + difficulty breathing), memory injection is **bypassed entirely**. The system prompt is replaced with an emergency response template:

```
⚠️ 检测到可能危及生命的症状。请立即拨打120或前往最近医院的急诊科。
本工具无法处理紧急情况。
```

This ensures no historical context dilutes the critical emergency warning.
