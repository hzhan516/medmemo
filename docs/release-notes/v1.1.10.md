# MedMemo v1.1.10 Release Notes

> 简体中文版本见 [`docs/i18n/zh-Hans-CN/release-notes/v1.1.10.md`](../i18n/zh-Hans-CN/release-notes/v1.1.10.md).

## Overview

MedMemo v1.1.10 is a release-hardening update focused on making the stable release pipeline, checksum verification, and update path more robust and auditable. There are no new diagnostic or treatment features.

**Important:** MedMemo is a personal health-information assistant. It is **not a medical device**, does **not diagnose**, does **not prescribe**, and does **not recommend treatments**. Always follow the advice of qualified healthcare professionals.

## Highlights

- **Release pipeline hardening**: stable releases now go through a two-stage Draft workflow with mandatory `production-release` Environment approval before becoming public.
- **Checksum fail-closed**: every installer is recorded in a single six-file manifest; `checksums.txt` is verified before any update download and again during installation.
- **Windows data directory**: legacy data directory is preferred for upgraded users; if the install directory is not writable, MedMemo falls back to `%USERPROFILE%\.medmemo\data`.
- **macOS and Linux data directory**: the default remains `~/.medmemo/data` for compatibility; use `MEDMEMO_DATA_DIR` or `config.yaml` to override it.
- **Linux package updates**: DEB and RPM install kinds are detected so the updater can select the correct asset; AppImage remains the portable default.
- **Evidence workflow**: five-platform test evidence is recorded via `record-release-test.yml` and validated by `finalize-release.yml` before publication.

## Windows

### Legacy data directory takes priority

When both an old data directory and the new install-directory data folder exist, MedMemo prefers the legacy location so that existing records remain visible after upgrade. If you started using a release candidate and stored data in the new install-directory location, set `MEDMEMO_DATA_DIR` or use `config.yaml` to point to that folder explicitly.

### Fallback when install directory is not writable

On fresh installs or upgrades where the install directory (for example, `C:\Program Files\MedMemo`) is not writable, MedMemo automatically falls back to `%USERPROFILE%\.medmemo\data`. No automatic migration, deletion, or merge of databases is performed.

## Linux

### DEB/RPM users upgrading from release candidates

If you installed a v1.1.10 release candidate from a DEB or RPM package, you must manually install the final DEB/RPM package once. The automatic updater can select the correct package once the installed kind is detected, but it cannot switch from an unlabeled RC package without this one-time manual overlap.

### AppImage

The AppImage is portable and receives updates in place. Make sure the file is executable (`chmod +x`) before running it.

## Checksum verification

All release assets are listed in `scripts/build/release-assets-manifest.json`. During an update:

1. The updater refuses to download if the expected checksum is empty.
2. The downloaded file is verified against the checksum; any mismatch deletes the temporary file and prompts you to try again later.

You can also verify manually:

```bash
sha256sum -c checksums.txt
```

## Known Limitations

- macOS ARM assets are built and checked in CI; real-device validation is a residual risk that is tracked in the release evidence.
- Linux arm64 DEB/RPM packages are not included in this release.
- The updater will not download an update when checksum information is unavailable; the new version will still be visible in the UI.

## What MedMemo Does Not Do

MedMemo is designed to help you organize and recall health-related information. It does **not**:

- Provide definitive diagnoses.
- Recommend specific drugs, dosages, or lab orders.
- Create treatment plans or recommend surgery.

If you experience a medical emergency, call your local emergency number or visit the nearest emergency department.
