# v1.1 Prompt 工程指南 — 记忆注入

> 🌐 [English Version](../../../design/v1.1-prompt-engineering.md)

> 本文档描述 MedMemo v1.1 记忆注入中使用的提示词设计、格式化模板和 Token 预算策略。面向需要理解或修改历史记忆如何输入 LLM 上下文窗口的后端工程师、AI 集成开发者和技术评审人员。

---

## 1. 设计原则

记忆注入提示词遵循三条核心原则：

| 原则 |  rationale |
|:---|:---|
| **非侵入性** | 注入的记忆不应打断自然对话流。LLM 应将其视为软性背景上下文，而非刚性指令。 |
| **可追溯性** | 每条注入事实必须携带来源信号（置信度分数、时间戳），使 LLM 能校准其依赖程度。低置信度事实以试探性措辞呈现。 |
| **合规优先** | 敏感事实（`IsSensitive = true`）默认被排除。无 PII、药品名称或诊断结论会在未经用户明确批准的情况下进入提示词。 |

---

## 2. 注入触发条件

记忆并非每轮都注入。`MemoryRetriever` 评估两个触发信号：

### 2.1 实体提及检测

```go
func detectEntityMentions(currentMsg string, facts []*ExtractedFact) []*ExtractedFact
```

- 将 `currentMsg` 切分为词元（简单的空白 + 标点分割）
- 对每个已批准事实，检查 `fact.Subject` 是否作为子串出现在任意词元中
- 返回按时间排序的匹配事实

**为何使用简单子串匹配而非语义 NER？**

- 延迟预算：触发检测必须在 <5ms 内完成
- 下游语义搜索（sqlite-vec）已提供高质量召回；实体提及检测是快速预过滤，在无重叠时跳过向量搜索
- 未来改进：若基准测试显示误报率 >10%，可替换为 ONNX NER

### 2.2 会话间隙检测

```go
const SessionGapThreshold = 10 * time.Minute
```

- 若当前会话的最后一条消息超过 10 分钟，检索器假设用户可能已丢失上下文
- 自动召回会话历史中最相关的 top-N 事实（非全部事实，避免 token 膨胀）

## 3. 记忆格式化模板

### 3.1 核心模板

```go
func FormatMemoriesForInjection(facts []*ExtractedFact, maxTokens int) string
```

**输出格式**（中文，与 MedMemo UI 语言一致）：

```
[相关背景信息]
1. {subject} {predicate} {object}（置信度: {confidence}）
2. {subject} {predicate} {object}（置信度: {confidence}）
...
```

**示例**：

```
[相关背景信息]
1. 用户 提到 最近一周睡眠质量较差（置信度: 0.85）
2. 用户 有 高血压家族史（置信度: 0.72）
3. 用户 正在 服用维生素D补充剂（置信度: 0.68）
```

### 3.2 置信度级别措辞规则

| 置信度范围 | 措辞风格 |
|:---|:---|
| ≥ 0.80 | 作为事实陈述：`用户 提到 ...` |
| 0.60 – 0.79 | 带缓冲前缀：`用户 曾提及 ...` |
| < 0.60 | 被排除（由 `ConfidenceThreshold = 0.6` 过滤） |

**为何基于置信度的缓冲？**

- LLM 提取的事实可能包含幻觉。低置信度事实以"用户曾提及"而非绝对陈述呈现，降低 LLM 将不确定信息当作事实的风险
- 这与 MedMemo 的合规立场一致：工具提供参考信息，不做诊断

### 3.3 敏感度排除规则

```go
if fact.IsSensitive {
    continue   // 跳过 — 从不注入敏感事实
}
```

被标记为敏感的事实（如包含手机号、身份证号或姓名，由 `desensitizer.RuleEngine` 检测）被完全排除在格式化输出之外。当前版本这是一条硬规则，无覆盖机制。

## 4. Token 预算管理

### 4.1 预算分配

```go
const (
    MaxInjectionTokensRatio = 0.20   // 系统提示词预算的 20%
    DefaultMaxInjectionTokens = 500
)
```

注入文本被限制在系统提示词总 token 预算的 20%（默认 500 token）。这防止历史记忆压垮当前对话上下文。

### 4.2 淘汰策略

当格式化记忆超出 token 预算时：

1. **排序**：按综合分数 `score = confidence * time_decay_factor`（越高 = 越相关）
2. **截断**：从底部移除 — 先移除分数最低的事实
3. **重新格式化**：对剩余事实重新格式化并重新计数 token
4. 若单条事实超出整个预算，则本轮完全跳过注入

**为何不使用 LRU？**

- 记忆注入优先**相关性**而非**新近性**。三周前的高度相关事实（如慢性病）比昨天的普通事实更有价值
- 综合分数已融入时间衰减，因此淘汰顺序自然平衡两个维度

### 4.3 Token 计数方法

```go
func estimateTokens(text string) int {
    return utf8.RuneCountInString(text) / 3   // 近似：中文 1 token ≈ 3 runes
}
```

- 使用轻量级启发式而非导入完整 tokenizer
- 对于中文为主的提示词，3-runes-per-token 近似在目标模型（GPT-4、Kimi、Qwen）的实测 token 计数误差在 10% 以内
- 未来改进：集成本地 BPE tokenizer 实现精确计数

## 5. 系统提示词集成

### 5.1 完整系统提示词结构

```
{BaseSystemPrompt}

{ComplianceDisclaimer}

{InjectedMemories}   // ← v1.1 动态区域

{CurrentTurnContext}
```

**BaseSystemPrompt**（静态）：

```
你是一款健康咨询信息工具，不诊断、不治疗、不开具处方。
你的职责是提供结构化健康信息参考，帮助用户理解症状、就医流程和科室选择。
紧急情况请建议用户拨打120。
```

**ComplianceDisclaimer**（静态，每会话）：

```
本工具仅提供健康信息参考，不诊断、不治疗，紧急情况请拨打120。
```

**InjectedMemories**（动态，每轮）：

```
[相关背景信息]
1. ...
2. ...
```

### 5.2 注入位置 rationale

记忆放置在**基础系统提示词和合规免责声明之后**，但在**当前轮次上下文之前**。此顺序确保：

1. LLM 首先理解其角色和边界（基础提示词）
2. 然后接收历史上下文（记忆）作为补充背景
3. 最后聚焦于当前用户消息（当前轮次）

记忆放置过早可能使 LLM 将其当作刚性指令；放置过晚则降低其对回复的影响力。

## 6. 可开关注入

### 6.1 全局开关

```go
func (r *MemoryRetriever) SetEnabled(enabled bool)
func (r *MemoryRetriever) IsEnabled() bool
```

- 持久化到检索器结构体的布尔字段
- 禁用时 `RetrieveForContext` 立即返回空切片

### 6.2 会话级开关

```go
func (r *MemoryRetriever) SetSessionEnabled(sessionID string, enabled bool)
func (r *MemoryRetriever) IsSessionEnabled(sessionID string) bool
```

- 存储在内存 map（`map[string]bool`）中，会话范围
- 允许用户说"换个话题" — 前端可调用 `SetSessionEnabled(sessionID, false)` 暂停注入，不影响其他会话

### 6.3 对提示词的影响

注入禁用时，系统提示词直接省略 `[相关背景信息]` 区域。不插入占位文本，保持提示词干净并节省 token。

---

## 7. 提示词中的合规护栏

### 7.1 禁止内容过滤

注入前，每条事实经过合规预检：

| 内容类型 | 操作 |
|:---|:---|
| 诊断结论（如"你患有XX病"） | 提取时拒绝；永不进入注入 |
| 药品剂量建议 | 拒绝；由合规拦截器标记 |
| 具体治疗方案 | 拒绝；由合规拦截器标记 |
| 敏感 PII（`IsSensitive = true`） | 从注入中排除 |

### 7.2 紧急症状处理

若当前用户消息触发 **A级-立即就医** 紧急关键词（如胸痛 + 呼吸困难），记忆注入**完全绕过**。系统提示词替换为紧急响应模板：

```
⚠️ 检测到可能危及生命的症状。请立即拨打120或前往最近医院的急诊科。
本工具无法处理紧急情况。
```

这确保历史上下文不会稀释关键紧急警告。
